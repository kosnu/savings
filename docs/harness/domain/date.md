# Date Domain Rules

## Rules

- date-only文字列は `yyyy-MM-dd` 形式で扱う。
- 日付だけを表す文字列はローカル日付として扱う。
- 対象月は年と月の組み合わせで表す。
- 月初日は対象日の年・月の1日として扱う。
- 月末日は対象日の月末日として扱う。
- 月次予算の有効開始日は対象月の月初日として保存する。

## アプリで扱う年月範囲

- 入力・日付変更・検索・集計の対象は2022年1月1日から2032年12月31日まで（両端を含む）とする。年月では2022年1月から2032年12月までとする。
- 2026年時点の家計管理で過去約4年の振り返りと未来約6年の予定を扱い、従来の月選択で扱えた期間を維持する。1900年や遠い未来へ広げない。範囲は固定し、年替わりによって保存済み履歴を対象外にしない。期間の延長は全機能を一緒に見直す。
- Webの日付ドメインが上下限と判定を所有し、カレンダー、月選択、フォーム、保存入力、URL、検索期間、現在日付に由来する初期値で共有する。DBが保持できる日付範囲や、月予算writeの現在月に基づく認可は変更しない。
- 不正・範囲外の検索年月は許容範囲内の現在月へ置き換える。現在月自身が範囲外なら最寄りの端の月を使う。有効な年月の片方だけが指定された場合は現在月の不足分を補完し、組み合わせが範囲外なら同じfallbackを使う。URL、月表示、取得期間を一致させ、詳細IDやカテゴリ条件は保持する。
- 現在日付を入力の既定値や操作対象に使う場合も範囲内へ収める。頻出支払いの参照期間は下限を越えない。作成日時・更新日時などの監査用timestampは対象外とする。
- 既存の範囲外データは削除・日付の自動補正をしない。直近一覧とID指定の詳細では元の日付を表示し、支払いの日付を範囲内へ訂正できる。日付以外の更新・削除と保存済み予算履歴を維持する。詳細遷移では検索年月だけを上記の有効なfallbackへ正規化し、保存日を検索条件として偽らない。
- 現在月の月予算設定は、実際の現在月が範囲外なら対応期間を示して取得・作成・編集・無効化を開始しない。補正した過去月の表示にDB現在月への更新を接続しない。
- 範囲外の月の検索・集計・CSV出力は受け付けない。範囲外から始まった予算の履歴が範囲内の月にも有効なら、その有効状態は保持する。
