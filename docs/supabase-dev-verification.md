# Supabase設定変更のDev確認手順

対象はDevとCI内の隔離環境。Prdには接続しない。
検証に関係するDB定義・権限・設定がDevと一致する場合、隔離環境の結果を利用し、Dev Hostedで同じ動作試験を繰り返す必要はない。
この文書は確認対象と満たすべき状態を定める。具体的な対象名・入力・操作・判定処理は
[CI検証コード](../tools/supabase-check/)とアプリケーションコードが所有する。
性能測定・負荷試験、取得上限超過時の一覧・集計、ブラウザの自動セッション更新の手動確認、
監視の担当・頻度・対応条件の決定、バックアップなどの復元元・復旧範囲の特定は対象外とする。

## CIで確認する内容

| 項目                | 満たすべき状態                                                                                                                                                                 | 確認時期               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------- |
| データ分離          | 本人に許可された操作は成功し、未認証者・別利用者は許可範囲外の情報を参照・変更できない。所有者の付け替えや他の所有範囲への関連付けでも境界を越えない。公開対象に試験漏れがない | コード・DB・権限変更時 |
| APIのセッション更新 | 更新後も同じ本人として認証され、許可された通常操作が成功する                                                                                                                   | 認証関連の変更時       |
| Auth設定            | Google providerが有効で、Site URL・redirect allow listが下記の値と一致する。追加で照合する項目は採用済み期待値があるものに限る                                                 | 関連設定変更時         |
| Web配信物           | ブラウザに渡されるのは公開可能な情報だけで、管理用の秘密情報が含まれない                                                                                                       | ビルド・配信ごと       |
| 公開・管理範囲      | 公開schemaにpublicを含み、公開テーブル・RPC・実効権限とDB定義がmigrationから構築した隔離DBと一致する。管理接続とサービスの確認基準は下記に従う                                 | 関連設定・DB変更時     |
| 通常操作と予算履歴  | 作成・更新・削除が意図どおり反映され、取得結果・集計と整合する。関係のない利用者の情報や過去の予算を変更しない                                                                 | コード・DB変更時       |

CIは合成データだけを使い、必要な正常操作と権限外操作を自動判定する。
Devの実設定は読み取りだけで照合する。試験の実行、設定の一致、Webの実配信を別の結果として扱う。
取得不能・権限不足・期待値未決定を成功にしない。秘密情報をログや検証結果へ出力しない。

## 照合する設定値

比較先は[Devプレビューの認証設定](development-preview.md#devプロジェクトと認証)とrepositoryのmigrationとする。
確認のために新しい設定方針や数値目標を決める必要はない。

- **接続先：** Dev projectは`Burneto Dev`、refは`ufekmuxkmodwydxmdbln`。Prdには接続しない。
- **Google認証：** Google providerを有効にし、Dev専用OAuth clientを使う。
  callbackは`https://ufekmuxkmodwydxmdbln.supabase.co/auth/v1/callback`。
- **アプリへの遷移先：** Site URLは代表Previewのorigin。
  redirect allow listは各Previewの正確な`https://<preview>-burneto-dev.<subdomain>.workers.dev/auth`。
  wildcardを使う場合は承認済みのaccount・Workerに限定し、`https://*.workers.dev/**`は使わない。
- **Data APIとDB権限：** 公開schemaに`public`を含み、テーブル・RPC・各roleの実効権限を隔離DBと照合する。
  追加の公開schemaがある場合は、その用途とアクセスできるroleを確認する。
- **管理接続：** アプリが使う`anon`・`authenticated`にsuperuser・BYPASSRLSを与えない。
  管理用token・secret key・DB管理接続はCIと管理者の用途に限定し、ブラウザへ渡さない。
- **サービス：** Auth・Data API以外のStorage・Realtime・Edge Functions等は、利用の有無とアプリ情報へのアクセス範囲を確認する。
  未使用サービスの全設定値の列挙は求めない。

セッション期限・同時ログイン制限・更新猶予・CAPTCHA・rate limit等は、採用済み期待値がある項目だけ追加照合する。
未変更の既定値に新たな方針を決めることや、全設定の棚卸しを完了条件にしない。
追加照合を省いた項目は確認済みと説明せず、Google経路への対策の適用有無も推測しない。

## 人が確認・決定する内容

| 項目           | 満たすべき状態                                                                                                                   | 確認時期                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 認証           | Dev専用OAuth clientとcallbackを照合し、Googleログイン後に本人としてアプリを利用できる。既に確認済みの同じ経路は再試験しない      | 初回・関連設定変更時                         |
| 公開・管理範囲 | 上記の設定値を満たし、CIで取得できない管理接続・サービスの利用有無とアクセス範囲も確認できている。例外は理由と所有者の合意を残す | 初回・関連設定変更時                         |
| 切り戻し       | 対象変更を戻す手順があり、戻せる範囲と元に戻せない・保証できない範囲が明確である                                                 | 対象変更ごとに一度。変更内容が変われば見直す |

切り戻しは手順と範囲の整備で完了とし、元の状態が不明な箇所を完全復元できると説明しない。
切り戻しのために、バックアップからの復元試験や元権限の完全復元を新たな完了条件にしない。

## 結果の扱い

Issue・PRでは、対象環境・commit、確認対象、期待する状態、実結果、合格・不合格・未確認を区別する。
CI成功を人の判断や未実施の実機確認の代用にしない。CIの実行条件・入力・権限・確認できない範囲は
[検証コードの案内](../tools/supabase-check/README.md)を参照する。
