# Supabase設定変更のDev確認手順

対象はDevとCI内の隔離環境。Prdには接続しない。
この文書は確認対象と満たすべき状態を定める。具体的な対象名・入力・操作・判定処理は
[CI検証コード](../tools/supabase-check/)とアプリケーションコードが所有する。

## CIで確認する内容

| 項目               | 満たすべき状態                                                                                                                                                                 | 確認時期                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------- |
| データ分離         | 本人に許可された操作は成功し、未認証者・別利用者は許可範囲外の情報を参照・変更できない。所有者の付け替えや他の所有範囲への関連付けでも境界を越えない。公開対象に試験漏れがない | コード・DB・権限変更時     |
| セッション更新     | 更新後も同じ本人として認証され、許可された通常操作が成功する                                                                                                                   | 認証関連の変更時           |
| Auth設定           | 認証方法・遷移先・セッション・不正利用対策の実設定が、所有者の採用した期待値と一致する                                                                                         | 関連設定変更時             |
| Web配信物          | ブラウザに渡されるのは公開可能な情報だけで、管理用の秘密情報が含まれない                                                                                                       | ビルド・配信ごと           |
| 公開・管理範囲     | 公開範囲・接続経路・権限・サービスが承認された用途に限定され、DBの適用状態が検証対象と一致する                                                                                 | 関連設定・DB変更時         |
| 通常操作と予算履歴 | 作成・更新・削除が意図どおり反映され、取得結果・集計と整合する。関係のない利用者の情報や過去の予算を変更しない                                                                 | コード・DB変更時           |
| 取得上限           | 上限を超える情報を扱っても、欠落した一覧・集計を全件の結果として扱わない                                                                                                       | 取得・集計処理・上限変更時 |

CIは合成データだけを使い、必要な正常操作と権限外操作を自動判定する。
Devの実設定は読み取りだけで照合する。試験の実行、設定の一致、Webの実配信を別の結果として扱う。
取得不能・権限不足・期待値未決定を成功にしない。秘密情報をログや検証結果へ出力しない。

## 人が確認・決定する内容

| 項目                 | 満たすべき状態                                                                                                                       | 確認時期                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| 認証と保護範囲       | Googleログイン後に本人としてアプリを利用できる。セッション・不正利用対策の期待値と、保護対象外の扱いが決まっている                   | 初回・関連設定変更時                         |
| 公開・管理の採用判断 | 必要な公開範囲・接続元・サービス・管理権限が決まっており、例外に理由と所有者の合意がある。CIで取得できない実設定もこの判断と一致する | 初回・関連設定変更時                         |
| 監視条件             | エラー・容量・利用量の確認先、担当、頻度、対応を始める条件と対応内容が決まっている                                                   | 一度決定し、運用体制・基準変更時に見直す     |
| 復元元・復旧範囲     | 利用できる復元元と復旧可能な範囲が明確で、復元できない範囲と許容するデータ損失を所有者が明示的に受け入れている                       | 一度確認し、設定・構成変更時に見直す         |
| 切り戻し             | 対象変更を戻す手順があり、戻せる範囲と元に戻せない・保証できない範囲が明確である                                                     | 対象変更ごとに一度。変更内容が変われば見直す |

監視条件の決定と、日々の監視は別の作業とする。
復元元・復旧範囲の確認に、バックアップの定期実行・鮮度・失敗の継続監視は含めない。
切り戻しは手順と範囲の整備で完了とし、元の状態が不明な箇所を完全復元できると説明しない。

## 結果の扱い

Issue・PRでは、対象環境・commit、確認対象、期待する状態、実結果、合格・不合格・未確認を区別する。
CI成功を人の判断や未実施の実機確認の代用にしない。CIの実行条件・入力・権限・確認できない範囲は
[検証コードの案内](../tools/supabase-check/README.md)を参照する。
