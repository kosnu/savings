# 7日間の復帰猶予と午前3時からの分割削除を備えたアカウント削除を実装する

## 概要

関連: #1884。[アカウント削除設計](account-deletion.md)に従い、削除予約後の利用停止、期限内の復帰、期限後の物理削除を実装する。
予約・停止認可・再有効化・削除ジョブ・結果照会・日英Privacy・運用と回帰試験を一体で扱う。詳細契約と全観測条件の正本は設計書とする。

## 完了の定義 (Definition of Done)

- [ ] 「設定 → プロフィール」で表示名を編集でき、「設定 → アカウント」で登録メールアドレスを確認して削除を予約できる。確定前に削除対象・共有ブックへの影響・復帰条件を短く説明する。日英の案内とPrivacyでは認証方法を明示しない。確定前の取消ではデータを変えない。
- [ ] 現在ログイン中の本人が追加ログインなしで明示確定した予約を受け付け、DB時刻で申請から168時間の復帰締切と、その時刻以降で最初の03:00 `Asia/Tokyo` の削除開始予定を算出する。確定前に復帰と削除開始の時刻の目安を示す。受付を確認したら申請端末で一度だけ通知し、ログアウト後の通常のトップへ戻る。
- [ ] 予約中はAuth・全データ・所属を保持しつつ、旧JWT・別端末・旧Webからの新しい通常read/write・認証同期を拒否する。申請端末ではcache・遅延応答から通常データを再表示せず、物理削除後も旧認証情報で復活させない。
- [ ] 別端末やstorage消去後も、期限前に本人が開始した通常のログインと本人向け状態照会で取得した `request_id` で予約取消・再有効化でき、refresh・session復元では取り消さない。期限以降は処理待ちでも復帰不可。取消後の再申請は新しい期限と開始予定を持ち、旧要求の影響を受けない。
- [ ] 通常ログインのcallback `/auth` でOAuth継続を検証してから認証同期を始め、別のアカウントでは元の予約を取り消さない。古いcallback・失敗・marker期限切れで意図しないsession置換やuser/Book作成を起こさない。失敗時は当該ログインの一時情報だけを消去し、元sessionと他端末でrefreshできる。通常ログイン・プロフィール設定を維持する。
- [ ] ジョブは開始予定以降の毎日、日本時間03:00〜03:59だけ毎分最大10件（最大600件／日）を処理する。残件・失敗分は翌日の同じ時間帯へ回し、残件ゼロによる動的な有効化・停止は行わない。運営者は予定前の待機と障害・滞留を区別できる。
- [ ] Authと本人の関連情報、無人Bookと全履歴を原子的に削除する。他memberがいるBookはデータと利用を維持し、同時削除で無人Bookを残さない。途中失敗は全体rollbackし停止・再試行を維持する。
- [ ] 通信断・reload・JWT失効後も端末の保存情報で同じ受付を自動確認する。受付確認またはログアウトに失敗したときだけ、その操作を再試行できる。別端末は既存sessionでpendingを検知したら自動ログアウトして通常トップへ戻る。トップには予約の詳細を表示せず、受付用URL・復帰ボタン・照合情報の手入力を設けない。匿名照会は不正キーで情報を開示しない。受付やジョブ起動を削除完了とせず、照合情報紛失・記録期限切れによる確認不能も示す。
- [ ] pendingを処理完了まで保持し、終端記録は30日で照会停止・日次消去する。最大7日の運営者管理backupからの復旧でも最新要求状態と元の期限を適用し、期限延長・意図しない復帰・取消済み要求の削除・削除済みアカウント再公開を防ぐ。
- [ ] 設計の全観測条件を合成データで満たし、必要な検証と承認されたDevのAuth/Cron確認が成功する。今回のWeb配信と新規受付はDevに限り、Cronの定義と実行権限の設定手順は環境共通とする。Hostedの未検証事項を成功扱いせず、停止認可・ジョブ・Privacy・運用が揃うまで公開しない。

## 制約・禁止事項

- 予約・再有効化は本人、ジョブは管理roleに限定する。状態・期限・重複抑止をDBで強制し、開始予定は復帰締切から算出する。Authのbanや猶予中の先行削除は行わない。
- 管理secret・table直接権限をブラウザへ渡さない。確認キーはhashで保存し、URL・診断出力・問い合わせへ出さず、通常データや削除の権限に使わない。
- Googleアカウント削除・export・複数Book管理UI・所有権移譲・物理削除後の利用者向け復元は対象外。切り戻しでも既存予約の停止・復帰・削除・照会を維持する。
- Issue作成だけでは実装・DB適用・実データ削除を開始しない。対応の実行依頼後は実装・検証・レビュー・PR作成までを扱う。本番適用・外部設定・共有Dev変更・実アカウント試験は対象と影響を示して別途承認を得る。

## 固有の検証

- 168時間と03:00の直前・同時・直後、timezone差・lock待機、取消後の再申請、11件以上・ジョブ停止再開・03:59/04:00の起動境界と翌日の再開を確認する。先頭1件の連続timeoutを単件で切り分け、pendingのまま次回試行を延期して残り10件を進め、原因解消後に延期分も完了できることを確かめる。
- 並行要求・失敗注入・通信断・旧認証情報とOAuth継続の異常系、30日境界とbackup復旧を、設計の観測条件に沿って確認する。
- Google新session・通常callbackでの本人照合・Hosted認可・Cronと処理容量は承認されたDevで照合する。SQL単体・MSW・[HTML解説](account-deletion.html)で実動作を検証済みとしない。
