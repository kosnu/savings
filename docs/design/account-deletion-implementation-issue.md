# 7日間の復帰猶予と午前3時からの分割削除を備えたアカウント削除を実装する

## 関連Issue

#1884

## 概要

利用者がアカウント削除を予約するとBurnetoを利用停止にし、7日以内の本人の新しいGoogleログインで予約を取り消して同じデータへ復帰できるようにする。
申請成立から168時間を過ぎたら復帰を受け付けず、その期限以降で最初の午前3時（日本時間）からAuthと関連データを小分けに物理削除する。
午前3時は削除開始の下限とし、毎分最大10件ずつ処理する。残件・失敗分は以後のジョブで継続し、開始予定を削除完了時刻として約束しない。

[アカウント削除設計](account-deletion.md)に従い、予約・停止認可・再有効化・期限後ジョブ・結果照会・日英Privacy表示・運用と回帰試験を一体で実装する。
[HTML解説](account-deletion.html)は設計理解のためのシミュレーションであり、実動作の検証結果として扱わない。

## 完了の定義 (Definition of Done)

- [ ] 確定前に、削除対象・保持情報・共有家計簿への影響・Googleアカウントは消えないこと・168時間の取消猶予・ログインで予約取消・期限後の復元不可・その後の最初の午前3時からの分割削除を理解できる。確定前の取消ではデータが変わらない。
- [ ] 予約は直近5分以内の本人sessionだけが確定でき、DB時刻から168時間の復帰期限とpending要求が一括保存される。「削除予約受付」・復帰期限・物理削除の開始予定を別表示し、Auth・アプリ内user・全データ・所属は未削除で保持される。
- [ ] 物理削除の開始予定は復帰期限以降で最初の03:00 `Asia/Tokyo` をDBで算出し、UTCの時刻で判定する。期限が03:00直前なら当日、同時なら同時刻、直後なら翌日とし、168時間未満へ繰り上げない。DB session・端末のtimezoneに依存させず、予約/状態/結果RPCが復帰期限と開始予定を返す。
- [ ] 予約中は旧JWT・refresh・別端末・旧Webを含め、公開table/RPCの通常read/writeと認証同期による再作成を拒否する。本人限定の状態照会・期限内再有効化だけを許可する。他memberの利用は継続する。
- [ ] 申請後の本人の新しいGoogleログインが期限未満で成立した場合だけ、同じ要求を取り消して元のアカウントを再有効化する。自動refresh・session復元・古いcallback・別identityでは取り消さない。
- [ ] 復帰期限直前・同時・直後とlock待機をDB時刻で判定し、期限以上は午前3時の開始待ち・ジョブ未実行でも復帰できない。取消後の再申請には新しい168時間とそこから算出する開始予定を設け、古い要求・ジョブが新しい予約へ作用しない。
- [ ] 毎分のジョブは開始予定と次回試行時刻が来たpendingを最大10件ずつ処理し、開始予定の1秒前は削除せず、同時刻以降に削除できる。11件以上の残件・停止後の再開・失敗再試行は元の開始予定を維持して以後も継続し、03時台で打ち切ったり翌朝まで改めて待たせたりしない。
- [ ] 開始予定以降のジョブはAuth user/identity/session/refresh、本人users/pin/membership、無人になるBookと全関連履歴を原子的に削除する。他memberが残るBookは全データと利用を維持し、同時削除で無人Bookを残さない。
- [ ] SQL途中例外・制約違反・Storage依存・完了記録失敗・ジョブ中断で部分削除を残さない。失敗要求は停止状態を維持し、失敗時のDB時刻から1分〜最大1時間の間隔で再試行される。開始予定前の待機と障害・滞留を運営者が区別でき、予約受付・復帰期限到来・開始予定到来・ジョブ起動だけで削除完了と表示しない。
- [ ] 予約/取消の通信断、reload、JWT失効後も受付番号と確認キーで要求状態を照会できる。不正キーでは情報を開示しない。照合情報紛失や終端から30日経過で確認できない場合は、その限界を明示する。
- [ ] OAuth継続のsessionを通常の認証同期から隔離し、別identity・失敗・期限切れは破棄する。元sessionの置換や意図しない別user/default Book作成を起こさず、通常ログイン・プロフィール設定は維持される。
- [ ] 予約時のcache/session消去と遅延応答破棄で通常データを再表示しない。物理削除後の旧JWT/refreshから通常データ取得・認証同期・refreshができず、削除済みAuth IDが復活しない。
- [ ] pendingは処理完了まで保持し、取消/完了記録は終端から30日で照会停止・日次消去する。運営者管理backupは最大7日とし、復旧時に最新要求状態と元の復帰期限を再適用して開始予定を再算出する。復旧時刻からの延長・意図しない復帰・取消済み要求の削除・削除済みアカウント再公開を防ぐ。
- [ ] 設計の全観測条件を合成データで満たし、Web必須検証・隔離DB試験・承認されたDevのAuth/Cron確認が成功する。未検証のHosted条件を成功扱いせず、停止認可・ジョブ・運用が揃うまで予約導線を公開しない。

## 制約・禁止事項

- 予約・再有効化は本人だけ、物理削除ジョブは管理roleだけが実行する。状態の正本・復帰期限・物理削除の開始予定・重複抑止をDBで強制し、ブラウザの時刻・sessionイベント名・user_metadataを認可に使わない。開始予定は復帰期限からの算出値とし、重複した状態列を作らない。
- Authをbanして復帰ログインを塞がない。猶予中にmembershipやデータを先に消さず、アプリの利用権限を停止する。
- ブラウザへ管理secretやtable直接権限を渡さない。結果確認キーはhashで保存し、URL・ログ・Sentry・問い合わせメールへ出さず、削除や通常データの権限に使わない。
- Googleアカウントの削除、export、複数Book管理UI、所有権移譲、物理削除後の利用者向け復元は追加しない。
- 切り戻しでも既存予約の停止・期限内復帰・期限後削除・照会を放置しない。新規予約の停止とジョブ障害への対処を分ける。
- このIssueの作成自体では実装・DB適用・実データ削除を開始しない。対応の実行依頼後は実装・必要な検証・レビュー・PR作成までを扱う。本番適用、管理権限/Cron等の外部設定、共有Dev変更、実アカウント試験は対象と影響を提示して別途承認を得る。

## 補足

検証は設計の「後続実装の完了条件と検証」に従う。
Webはformat後にlint・format-check・typecheck・unit/integration test、対象storyが該当すればStorybook browser testを実行する。
DBは隔離SupabaseのpgTAP、並行transaction、失敗注入、REST/RPCの停止認可と旧JWT/refresh拒否を確認する。
Google callback隔離・新sessionでの期限内再有効化、午前3時の開始境界・Cron起動・再試行・10件超の分割処理容量は承認されたDevの合成アカウントで照合する。
