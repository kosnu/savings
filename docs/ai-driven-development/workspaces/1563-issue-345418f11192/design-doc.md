## 採用する構成

永続層は `public.users.language`、Webのprofile取得・更新境界、認証session境界、language同期provider、設定selectorで構成する。認証済み初回表示はアカウント言語の取得成功またはfallback決定をready条件とし、取得済みアカウント値を端末値より優先する。言語変更はprofile write契約で保存し、write失敗は直前値への復帰と通知を同じ操作境界で扱う。write成功後の内部再取得失敗は保存失敗へ読み替えず、query境界が後続取得で収束させる。

architecture baseline: Git HEADの「採用する構成」sectionはschema v3 target\_stateを正本とする完成状態へ再構成する。

## データ・API境界

`language` は `en`、`ja`、未設定の `null` を保持する。認証済みクライアントが更新できるprofile列は `name` と `language` に限定し、対象は認証中ユーザーに対応する1行とする。取得は表示名、email、languageの必要列を返し、更新対象0件とAPI errorを成功扱いにしない。MSW fixtureはこのresponse shapeとprofile GET/PATCH境界を再現する。

data\-contract baseline: Git HEADの「データ・API境界」sectionはschema v3 target\_stateを正本とする完成状態へ再構成する。

## 状態遷移と優先順位

認証状態の確定前はユーザー向け画面を確定表示しない。未認証では端末言語または既定値で利用可能にする。認証済みではprofile取得を開始し、account languageがあれば端末へ反映し、未設定なら端末値を維持し、取得失敗ならfallback決定後に表示する。selector操作では選択値をprofileへ保存し、write失敗時だけ直前言語へ戻して通知する。write成功後のcache収束失敗は選択値を戻さず、ユーザー向け保存失敗通知を出さない。

state\-flow baseline: Git HEADの「状態遷移と優先順位」sectionはschema v3 target\_stateを正本とする完成状態へ再構成する。
