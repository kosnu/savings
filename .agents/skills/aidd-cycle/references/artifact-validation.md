# AIDD Artifact Validation

Use this reference for Requirements and Design phase execution and for the
Build phase entry check.

## Structural Model

Managed AIDD artifacts use schema version 2.

- Goal inputs: temporary `requirements_goal` or `design_goal` JSON.
- Cycle title owner: `validation.cycle_start_issue_title` in the Requirements
  Goal and canonical Requirements artifact. Later gates derive it from those
  validated bytes and never accept another title input.
- Canonical artifacts:
  `docs/ai-driven-development/workspaces/<workspace>/requirements.json` and
  `design-doc.json`.
- Display outputs: `requirements.md` and `design-doc.md`, generated by
  `render_aidd_artifact.py`.
- Phase handoff:
  `<workspace>/.aidd/design-completion.json`, captured only after Design
  validation and verified unchanged at Build entry and completion.

The validators enforce canonical paths, regular non-symlink inputs, Issue
snapshot identity, full inventories, baseline hashes, rule dependencies,
transition status, block references, evidence roles, and evidence owners.
Schema v2 additionally enforces canonical headings, substantive non-placeholder
text, unique evidence references, and unambiguous evidence-to-owner mapping.

## Workspace

```sh
python3 .agents/skills/aidd-cycle/scripts/validate_workspace.py \
  --repo-root <repo-root> \
  --issue <owner/repo#number> \
  --issue-title <current-issue-title>
```

Use the workspace printed by the validator. It reuses the sole existing
workspace or derives the only first name from the complete normalized Issue
title; callers do not supply a hand-written candidate.

## Requirements Goal

Save the exact fetched Issue body and proposed Goal JSON in temporary regular
files. Run both commands before `create_goal`:

```sh
python3 .agents/skills/aidd-cycle/scripts/validate_requirements_goal.py \
  --issue <owner/repo#number> --issue-title <current-issue-title> \
  --issue-url <canonical-url> \
  --issue-updated-at <updatedAt> --issue-body <issue-body-file> \
  --document <requirements-goal-json> --rule-map docs/harness/rule-map.json \
  --repo-root <repo-root> --kind goal

python3 .agents/skills/aidd-cycle/scripts/validate_requirements_continuity.py \
  --issue <owner/repo#number> --issue-body <issue-body-file> \
  --issue-title <current-issue-title> \
  --document <requirements-goal-json> --kind goal \
  --repo-root <repo-root> --workspace <workspace>
```

The Goal must snapshot the Issue, select at least one direct rule, include its
declared dependency closure, inventory every current and baseline requirement
and required section, and classify explicit retirements. Evidence quotes must
come from the snapshotted Issue, occur in their owned content, and be unique per
changed or new requirement and per changed or new section. Retirement evidence
must name the ID and explicitly state retirement without negating it.

  --goal-document <requirements-goal-json>

python3 .agents/skills/aidd-cycle/scripts/validate_requirements_continuity.py \

## Design Goal and Artifact

Revalidate the canonical Requirements artifact first. Then use the Design gate
for the temporary Goal JSON and again for the canonical artifact:

```sh
python3 .agents/skills/aidd-cycle/scripts/validate_design_coverage.py \
  --issue <owner/repo#number> --issue-url <canonical-url> \
  --issue-updated-at <updatedAt> --issue-body <issue-body-file> \
  --rule-map docs/harness/rule-map.json \
  --requirements <canonical-requirements-json> \
  --document <design-goal-json> --kind goal \
  --repo-root <repo-root> --workspace <workspace>

python3 .agents/skills/aidd-cycle/scripts/render_aidd_artifact.py \
  --source <design-json> --output <design-md> --repo-root <repo-root>

python3 .agents/skills/aidd-cycle/scripts/validate_design_coverage.py \
  --issue <owner/repo#number> --issue-url <canonical-url> \
  --issue-updated-at <updatedAt> --issue-body <issue-body-file> \
  --rule-map docs/harness/rule-map.json \
  --requirements <canonical-requirements-json> \
  --document <design-json> --kind artifact \
  --repo-root <repo-root> --workspace <workspace> \
  --goal-document <design-goal-json>
```

Each requirement must own one design evidence reference and one verification
evidence reference. Each replaced baseline section must own baseline evidence.
Hashes decide preserved versus replaced; headings remain display labels.
`product_behaviors` is the complete typed inventory of added, changed, or
removed user operations and state transitions. Every `PB-*` record has one
canonical `requirement_id`. Canonical Requirement content remains only in the
validated `requirements.json` snapshot. Exactly one design-evidence owner with
the same Requirement ID owns the record. There is no generic source kind or
copied behavior prose. Selected rules constrain Requirements and Design but
never define product behavior directly or substitute for a missing Requirement.
Design prose does not define behavior outside this inventory.

After the artifact command succeeds, capture the Design-owned completion
receipt before completing the Design Goal:

```sh
python3 .agents/skills/aidd-cycle/scripts/capture_design_completion.py \
  --issue <owner/repo#number> --issue-url <canonical-url> \
  --issue-updated-at <updatedAt> --issue-body <issue-body-file> \
  --rule-map docs/harness/rule-map.json \
  --repo-root <repo-root> --workspace <workspace> \
  --goal-document <design-goal-json>
```

Record the exact receipt path and printed SHA-256 in the Design completion
evidence. The receipt snapshots the fully revalidated retained Design Goal hash,
Requirements-owned cycle title, Issue body, canonical rule map, every selected
rule document, and the canonical
source and display paths and hashes. Capture reads those inputs and the Git
`HEAD` Requirements / Design baselines once, validates and renders from those
exact bytes, constructs the receipt from the same bytes, and fails if any input
differs when the final drift check reads it again. The validated snapshot bytes,
not path permanence, are the completion identity.

## Build Entry

Take the receipt path and SHA-256 from the preceding Design Goal completion
evidence. Immediately before constructing the Build Goal, fetch the current
Issue body, canonical URL, and `updatedAt`, then run:

```sh
python3 .agents/skills/aidd-cycle/scripts/validate_build_entry.py \
  --issue <owner/repo#number> --issue-url <canonical-url> \
  --issue-updated-at <updatedAt> --issue-body <issue-body-file> \
  --rule-map docs/harness/rule-map.json \
  --repo-root <repo-root> --workspace <workspace> \
  --expected-receipt-sha256 <design-completion-sha256>
```

The command loads the receipt bytes whose SHA-256 was recorded by Design, then
loads the Issue, rule map, selected rules, Requirements, Design, displays, and
Git `HEAD` Requirements / Design baselines once. It revalidates Requirements Input and Continuity,
Design coverage, Requirement-owned product behavior, and generated displays
from that immutable byte snapshot. It requires the snapshot to equal the
receipt and performs the same final drift check. Later
Build comparisons use the already loaded receipt bytes and recorded SHA-256;
they do not treat continued occupancy of the receipt path as identity. The
cycle title is derived from canonical Requirements and must equal the title in
the receipt; there is no Build caller input that can replace it.

Create the Build Goal only when this command succeeds and prints the same
receipt SHA-256 recorded by Design. Put that receipt identity in the Goal, and
run the same command again before completing Build. The exact receipt recorded
by the preceding Design completion evidence is the Build phase's upstream
identity.
