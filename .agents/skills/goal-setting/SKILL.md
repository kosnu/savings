# Goal setting

Read `docs/ai-driven-development/codex-adapter.md`, `workflow.md` and
`goal-templates/index.md`. User instructions define authorization and scope.

Check the actual Goal tool and current Goal before creating one. Continue an existing
Goal for the same task; never replace an unrelated unfinished Goal. A paused Goal is
user/system-owned. Follow the host's terminal-state rules.

Build one compact objective containing Objective, Constraints, Done and Verification
from the authorized Task contract. Reference the repository task identity; keep detailed
Decision, hashes, progress and evidence in repository records. Do not create one Goal
per Requirements/Design/Build/Ship step. Do not run a legacy phase gate before setting it.

Call create_goal only when authorized, and set token_budget only when explicitly asked.
If tools are unavailable, say so and preserve the same Task contract for execution;
do not claim success or stop authorized work solely because Goal is unavailable.
Setting a Goal alone does not authorize executing a task when only Goal preparation was asked.
Learn has a separate Goal when requested and never continues into product implementation.
