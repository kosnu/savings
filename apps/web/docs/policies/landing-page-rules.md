# サービス紹介・利用開始画面のルール

未認証のサービス紹介・利用開始画面の設計と評価を扱う。LPという形式への適合ではなく、利用者の関心を
サービスの価値と利用体験につなぎ、利用開始を判断できる入口をつくる。
日常の記録・一覧・設定や認証フォーム自体には適用しない。紹介と操作が同居する
画面では領域ごとに目的を分け、操作領域には通常のWebルールを適用する。

## Intentから設計へ

個別の対象者、伝える価値、期待する行動はIssueのIntentを正本とする。
設計では、訪問者が何を知らない状態から、何を理解・想像して次の行動を選ぶかを
明示し、見出し・利用体験の見せ方・情報の流れ・主導線へ対応づける。
機能名や説明項目を揃えただけで、利用意欲を支える設計ができたと判断しない。

- 最初に目に入る領域で、どんなサービスで、誰のどんな場面に役立つかを伝える。
- 機能の説明は、それを使ったときの利点や具体的な利用場面につなげる。
- 利用体験を視覚的に想像できる表現を設計する。画面例、図、イラスト、文字と
  数値の構成などから目的に合うものを選び、何を伝える表現かを説明する。
- 情報の流れを価値の理解から利用開始へつなげる。主導線は行動と遷移先が分かる
  文言にし、補助情報が主導線や価値の訴求と競合しないようにする。
- 表現は実際に提供できる体験に基づける。例示と実データを区別し、未実装機能、
  実在しない実績・利用者の声、裏付けのない効果を訴求に使わない。

## 通常画面との適用境界

[DESIGN.md](../../../../DESIGN.md)のブランドと
[Web Design Rules](./design-rules.md)の共通規則を維持する。
サービス紹介の領域では、業務操作の密度優先・ヒーローや説明カードの一律禁止、上端配置、
固定の見出しサイズとレスポンシブ変更条件、ページ直下のgap指定に限り、
価値の伝達と読み順に合わせた構成を優先できる。採用した差分と目的を設計に記録する。

見出しの大小、余白、配置、視覚的な焦点を使って情報に強弱をつける。
ヒーロー・画像・カードの有無や数は完成条件にしない。
意味のない装飾や大きな空白を増やすだけで訴求を改善したことにしない。
色・フォント・角丸・shadow・余白のtoken、状態と操作の意味、金額などの
ドメイン表現、semantic構造とアクセシビリティは共通規則に従う。

## 実画面での評価

実装担当者は、対象の言語・テーマとモバイル／デスクトップの実画面を確認し、
Intentと設計に対応する次の観察結果をレビューへ記録する。

- 最初に目に入る内容からサービスと価値を理解できるか。
- 見出し、視覚表現、説明の関係から利用する場面と利点を想像できるか。
- 視覚的な強弱と読み順が、理解から主導線への流れを支えているか。
- 利用開始の行動と遷移先が明確で、実際に操作できるか。

可読性、横はみ出し、アクセシビリティ、動作の検証も行うが、それだけで
上記の目的を満たしたと判定しない。不足があれば構成・表現を修正して再確認する。
agentによる画面評価と、実ユーザーの利用意欲・転換率の測定は区別し、
未測定の効果を実証済みとして報告しない。
