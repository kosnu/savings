# エラー表示と復帰

エラー表示は、何が失敗し、どの操作で復帰できるかを利用者が判断するために置く。
すべての失敗を同じ部品へ揃えるのではなく、操作の文脈と、その場で判断・修正を続ける必要性から選ぶ。
ブランドの意味色は [DESIGN.md](../../../../DESIGN.md)、取得境界の復帰は
[Suspense Boundary Policy](suspense-boundaries.md)、保存完了の判定は
[Query Cache Policy](query-cache.md)に従う。

この文書は適用する表示方針を定義する。実装との差異と見直しの要否は変更対象のPRで照合し、
方針を記載しただけで既存実装の対応が完了したとは扱わない。

## 表示方式を選ぶ基準

次の順で、利用者が判断・操作する最小の範囲を選ぶ。

1. 入力のどこを修正するか特定できる場合は、その入力の直下へ表示する。
2. 入力や確認内容を保持して判断・再実行する場合は、フォーム、編集領域、確認ダイアログ内に残す。
3. 入力・確認面を伴わない単発操作の結果で、通知が消えても現在の状態と再操作先が分かる場合は、一時通知にする。
4. 必要なデータを取得できず表示を継続できない場合は、失敗した表示領域をエラーと復帰操作へ置き換える。
5. 局所的な表示では画面を継続できない場合だけ、ページ全体のエラーへ切り替える。

自動表示する任意の補助情報は、取得できなくても主操作を継続でき、利用者に「0件だった」などの誤った結果を伝えない場合に限り、非表示で継続してよい。
明示的に要求された操作の結果や、判断に必要な値を任意の補助情報として隠してはいけない。

通信元やHTTP statusだけで表示方式を決めない。API由来でも修正箇所が明確な制約は入力へ関連付け、
入力値が正しくても保存できない失敗を入力不正として扱わない。

| 文脈                           | 表示・配置                                                                                               | 表示期間と復帰                                                       |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 入力不正・修正対象が明確な制約 | 入力直下の `FieldMessages`。複数入力の関係なら修正先を示す                                               | 再検証で解消するまで残す。入力を保持して修正・再送信する             |
| フォーム全体の処理失敗         | フォーム上部の警告アイコン付き赤い `Callout`                                                             | 再送信開始、成功、取消まで残す。再送信中は処理中表示へ切り替える     |
| 1項目のインライン保存失敗      | 編集領域直下の小さい赤い処理失敗メッセージ                                                               | 編集値を保持し、再送信開始、成功、取消まで残す                       |
| 確認を伴う削除・解除の失敗     | 開いた確認ダイアログ内の赤い `Callout`                                                                   | 対象と確認内容を保持し、再実行または取消を選べるようにする           |
| 単発操作の結果                 | 操作対象が分かる文言の `Snackbar`                                                                        | 共通部品の表示時間または閉じる操作で消す。操作元から再実行できる     |
| データ取得失敗                 | 対象領域内の赤い説明と再試行操作。フォームや設定領域は `Callout`、一覧は一覧内、短い集計は値の近くに置く | 正常取得、表示条件の変更、離脱まで残す。同じ条件での再試行も提供する |
| 画面全体の継続不能             | `ErrorPage`                                                                                              | 再読み込みまたは安全な画面への移動を提供する                         |

`Callout` の既定は `color="red"`、`variant="surface"`、`size="1"`、警告アイコン付きとする。
ログアウトは削除と同一視せず、入力・確認面を伴わない単発操作として扱う。
削除でも確認画面がない別の操作を追加する場合は、その操作の文脈から選び直す。

## 文言、通知、表示の維持

- 失敗した対象・操作と、次にできる修正、再試行、再取得、再認証のいずれかを伝える。局所表示を「失敗しました」だけで済ませない。
- 入力や未送信の編集値を失敗時に消さない。入力を変更しただけで、通信・処理の失敗が解消したとは扱わない。
- 同じ失敗を局所表示と `Snackbar` の両方へ重複して出さない。成功は既存の一時通知を使い、処理失敗と同じ色にしない。
- 赤色だけで伝えず、説明を必ず置く。入力不正は `aria-invalid` と `aria-describedby` で入力へ関連付ける。保存・取得失敗だけを理由に入力を不正扱いしない。
- 動的に出すエラーには `role="alert"` または適切なlive regionを使う。同じメッセージを複数のlive regionへ重ねない。
- 再試行中は多重操作を防ぎ、結果が分かるまで処理中とする。再失敗しても操作先を失わず、成功時にフォーカス先が消える場合は復帰した領域へ移す。
- 取得失敗を0件、金額0、未設定、未分類で代用しない。取得できた他の領域は独立して使える状態を保つ。
- 認可の拒否、対象の消失など、同じ再送信では解決しない状態に単純な再試行だけを案内しない。対象の再確認や許可された画面への移動を示す。

## 書き込みと表示更新の区別

保存・更新・削除の完了は、必要な再取得まで含む。書き込みが終わったかと、最新表示を取得できたかを区別して伝える。

| 確認できている状態             | 説明と次の操作                                                                                             |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 書き込み失敗が確定             | 対象の保存・更新・削除を完了できなかったことを示し、修正または再送信を案内する                             |
| 書き込み成功後の再取得失敗     | 書き込みは完了したが表示更新ができないことを示し、再取得を案内する。全体の成功通知や完了遷移を先に出さない |
| 通信断などで書き込み成否が不明 | 結果を確認できないことを示し、まず現在状態を再確認する。未実行と断定して同じ操作を再送信させない           |

再取得だけで復帰できる状態を、作成の再送信による重複登録や、削除済み対象の再削除へ誘導しない。
結果の確実性を利用者が判断する必要のある状態は、一時通知だけで消さず、操作領域に残す。

## 既存の入力・操作への適用

以下は各操作が持つ文脈に対する表示方針である。表示期間・復帰は上表を適用する。
入力値や認可条件自体は変更せず、各ドメインの制約を適切な場所で伝える。

| カテゴリ固定数の上限                                                                                                                                                                                                                                                                                                                                         | 固定設定の近くへ上限と、固定を外す・別の固定を減らす選択肢を示す                                                      |

| [月次予算作成](../../src/features/budgets/createMonthlyBudget/CreateMonthlyBudgetForm/CreateMonthlyBudgetForm.tsx)・[更新](../../src/features/budgets/updateMonthlyBudget/UpdateMonthlyBudgetForm/UpdateMonthlyBudgetForm.tsx)                                                                                                                               | 修正箇所が明確な制約以外の処理失敗はフォーム全体 `Callout`                                                            |

## 既存の取得領域への適用

取得失敗はその表示の状態であり、単発の操作結果として `Snackbar` だけで伝えない。
同じ入力での再取得と境界reset、月・条件・ID変更時の復帰は [Suspense Boundary Policy](suspense-boundaries.md)に従う。

| 対象                                                                                                                                                                                                              | あるべき表示・復帰の判断                                                                                               |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| [ホーム](../../src/app/routes/HomePage/HomePage.tsx)・[支払いページ](../../src/app/routes/PaymentsPage/PaymentsPage.tsx)の前提データ                                                                              | 前提データに依存するページ領域に説明と再試行を出す。空白のfallbackにしない。前提データを共有しない領域まで巻き込まない |
| [支払い一覧](../../src/features/payments/listPayment/PaymentList/PaymentList.tsx)・[最近の支払い](../../src/features/payments/listPayment/RecentPayments/RecentPayments.tsx)                                      | 一覧領域内に対象を明示した説明と再試行。検索・移動など境界外の正常な操作は維持する                                     |
| [支払い詳細](../../src/features/payments/paymentDetails/PaymentDetailsOverlay/PaymentDetailsOverlay.tsx)                                                                                                          | 開いた詳細overlay内の説明と再試行。取得失敗と対象が存在しない状態を分け、閉じる操作も提供する                          |
| 支払い作成・編集と一覧フィルターのカテゴリ選択肢                                                                                                                                                                  | 選択欄の近くに取得失敗と再試行を示す。無効な「エラー」選択肢だけで済ませず、既存の選択値や他の入力を保つ               |
| [月次支出合計](../../src/features/summaryByMonth/MonthlyTotals/MonthlyTotals.tsx)・[カテゴリ集計](../../src/features/summaryByMonth/CategoryTotals/CategoryTotals.tsx)                                            | 該当集計の近くに対象を明示した赤い説明と再試行。予算など別責務の正常表示は維持する                                     |
| [予算利用額](../../src/features/budgets/components/MonthlyBudgetUsage/MonthlyBudgetUsage.tsx)                                                                                                                     | 差額を判断できない旨と再試行を値の近くに表示。上位の支出取得失敗も含め、単なる非表示や予算未設定と区別する             |
| [ブック情報](../../src/features/books/bookSettings/CurrentBookInformation/CurrentBookInformation.tsx)・[カテゴリ設定一覧](../../src/features/categories/components/CategorySettingsList/CategorySettingsList.tsx) | 対象設定領域内の `Callout` と再試行。未認証を取得失敗の同じ文言で代用しない                                            |

| [プロフィール](../../src/features/profile/profileSettings/AccountInformation/AccountInformation.tsx)                                                                                                              | アカウント情報領域の `Callout` と再試行。再取得成功後に入力フォームへ復帰する                                          |

## 認証・設定の復旧とエラーではない状態

| 状態                                                                     | あるべき表示・復帰の判断                                                                                                                         |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 初回セッション取得・ユーザー検証を完了できない                           | 認証を確認できない説明と再試行を、認証状態を確認する領域に残す。loadingのまま放置したり、通常の未ログインと同じ説明だけで済ませたりしない        |
| 有効なセッションの一時的な再検証失敗                                     | 認証契約に従い維持可能な状態を保ち、再検証が必要なら復帰操作を示す。一時障害を期限切れと断定しない。ユーザー切替時に旧ユーザーのデータを残さない |
| 再認証が必要と確認できるセッション失効・認証エラー                       | 利用制限の理由とログイン導線を継続先で表示する。単なるトップ画面への移動で理由を失わせない。APIコードの分類だけで全件を期限切れと断定しない      |
| 言語取得・端末保存の失敗でも契約どおりのfallbackで継続できる             | 主要操作を妨げる全体エラーにはしない。明示的な設定変更の保存ができなければ、その操作結果として通知する                                           |
| テーマの端末設定を読み書きできない                                       | 利用可能なテーマで継続し、変更の保存失敗は単発操作の結果として通知する。任意設定の例外でアプリ全体を使えなくしない                               |
| 不正なURL年月・形式不正のカテゴリ条件                                    | 既存の正規化契約に従って有効な条件へ戻す。正常に継続できる補正を通信エラーとして通知しない                                                       |
| 空一覧、予算未設定、未分類、不明カテゴリ、存在しない支払い               | それぞれのドメイン上の状態を説明する。取得失敗と混同せず、条件解除・別対象選択・一覧へ戻る操作を文脈に応じて示す                                 |
| [局所復旧できない画面障害](../../src/app/routes/ErrorPage/ErrorPage.tsx) | `ErrorPage` でページを表示できないことと再読み込み・ホーム移動を示す。監視・console出力だけを利用者向け表示の代わりにしない                      |

## 変更時の確認

エラー表示を変更する際は、失敗対象、入力保持、読み上げ、再操作、成功時の復帰を確認する。
書き込み後の再取得失敗と結果不明、条件変更・同条件での取得復帰も、関係する経路で確認する。
実際の操作とAPI境界を使う回帰確認は [Web Test Policy](test-policy.md)に従う。
